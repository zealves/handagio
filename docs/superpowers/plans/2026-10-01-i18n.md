# Multilingue (pt, en) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Handagio in Portuguese (pt-PT) and English, with one file per language, loading only the language in use.

**Architecture:** Our own small typed i18n in `src/i18n/`. `pt.ts` is the source of truth; `en.ts` has the same type. Each language is a lazy chunk (`import.meta.glob`, not eager); `main.tsx` waits for the initial language before mounting React. Musical naming (note names, chord symbol style) belongs to each language and is pushed into `src/audio/theory.ts` through `setNaming()`. Data that already carries Portuguese text (instruments, kits, chord modes, mouth effects, scale ids) keeps it; `pt.ts` derives from it, and `en.ts` lists every id.

**Tech Stack:** Vite 8, React 18, TypeScript strict, Zustand `persist`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-01-i18n-design.md`

## Global Constraints

- No new runtime dependencies.
- Store and preset ids stay unchanged (`scale: 'Maior'`, families, factory preset names, user preset keys).
- `src/vision` and `src/audio` do not import React. `src/audio/theory.ts` must not import `src/i18n` (the dependency goes the other way, via `setNaming`).
- Portuguese is pt-PT. English uses letter note names (C, C♯ … B) and compact chord symbols ("G7", "Dm", "Cmaj7", "C sus4").
- The main chunk carries no language texts. Language chunks are not in the service worker precache; they are cached when fetched.
- Docs (README, DECISIONS, CHANGELOG) stay in Portuguese. Commits are in English Conventional Commits.
- Before each commit: `npm run build && npm run lint && npm test`.
- Deviation from the spec, recorded in decision 66: status and notice texts are translated when they are set, not stored as keys.

## Review Focus

- Language saved as an unknown value (another version, edited localStorage): falls back to pt without crashing. Test in Task 1.
- Browser language `pt-BR` or `PT`: opens in Portuguese; `fr-FR`, empty `navigator.languages`: English. Test in Task 1.
- Switching language while the sheet is open with a chord preview and the HUD note on screen: every visible name (notes, chord labels, tabs) changes at once, with no mix. Test in Task 8 (e2e).
- Offline after the first visit in English: the app still opens in English (the en chunk is cached when fetched). Test in Task 3 (sw precache list) and Task 8 (en chunk requested once).
- Old user presets and stored `scale: 'Menor harmónica'` keep loading and show the translated label. Test in Task 4.

### Task 1: i18n core (registry, detection, loading, store)

**Files:**

- Create: `src/i18n/types.ts`, `src/i18n/index.ts`, `src/i18n/locales/pt.ts` (skeleton), `src/i18n/locales/en.ts` (skeleton), `src/i18n/i18n.test.ts`
- Modify: `src/state/store.ts` (pref `lang`), `src/ui/shell/logic.ts` (`sanitizePrefs`)

**Interfaces:**

- Produces:
  - `type Lang = 'pt' | 'en'`, `LANGS: Lang[]`, `LANG_NAMES: Record<Lang, string>` (each in its own language)
  - `detectLang(saved: unknown, navLangs: readonly string[]): Lang`
  - `loadLang(lang: Lang): Promise<Messages>` (cached per lang)
  - `setLang(lang: Lang): Promise<void>` (loads, sets `naming`, updates the store, document `lang`, title and description)
  - `t(): Messages` (current messages; throws if called before the first load)
  - `useT(): Messages` (React hook; re-renders when `lang` changes)
  - `type Messages` = the type of the `pt` default export

- [ ] Step 1: tests in `src/i18n/i18n.test.ts`: `detectLang` (`'en'` saved wins; `'xx'` saved is ignored; `['pt-BR']` → pt; `['PT']` → pt; `['fr-FR','pt-PT']` → pt, the first match wins; `['fr-FR']` → en; `[]` → en); `loadLang('en')` resolves an object with `meta.title`; `sanitizePrefs({ lang: 'xx' })` → `{ lang: 'pt' }`.
- [ ] Step 2: run `npx vitest run src/i18n` → fails (module missing).
- [ ] Step 3: implement. `index.ts` uses `const loaders = import.meta.glob<{ default: Messages }>('./locales/*.ts')`, key `./locales/${lang}.ts`. `useT` = `useStore((s) => s.lang)` and then `current` (module-level messages, set before the store changes). Store: `lang: Lang` in `Prefs` (default `'pt'`; the real initial value comes from `detectLang` in `main.tsx`). `sanitizePrefs`: `lang` not in `LANGS` → `'pt'`.
